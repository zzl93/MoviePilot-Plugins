# PT 魔力计算器插件 - 需求分析（做种数据来源与左右表结构）

本文档仅描述需求与约束；实现时若现有代码与需求不符，应以需求为准修改代码。

---

## 一、做种数据来源

### 需求

- **唯一数据源**：做种列表（左侧）只来自插件的**站点种子主表与站点种子快照表**（及本需求所述方式写入的数据）；右侧下载器种子数据来自**下载器种子主表与下载器种子快照表**。不再依赖主项目的 torrent_activity 或站点用户数据表里的做种列表；主项目已无 torrent_activity 字段。
- **无数据时自动补数**：当某站点在插件**站点种子主表与站点种子快照表**中没有任何做种记录时，应自动通过**页面解析**拉取该站做种页，将解析结果写入**站点种子主表与站点种子快照表**，再基于插件表返回数据。
- **站点刷新消息驱动**：主项目在刷新站点用户数据后会发送站点刷新相关消息。插件应监听该消息，在收到某站点的刷新事件时，解析该站点做种数据并写入**站点种子主表与站点种子快照表**，使插件表与该站点最新状态保持同步。
- 页面解析与落表逻辑应可复用（无数据时补数、与刷新消息触发时），且不依赖主项目用户数据表；所需站点信息（如 url、cookie 等）在仅使用插件配置/plugindata 的前提下可获得。

---

## 二、左右数据统一：四张表，Page 展示分两表，右数据仅缺时从下载器拉取

### 数据模型

- 插件有四张表：**站点种子主表**、**站点种子快照表**、**下载器种子主表**、**下载器种子快照表**（见第四节表结构）。
- **左侧（站点做种）**：数据来自**站点种子主表** + 该种子在**站点种子快照表**中的**最新一条**（按 snapshot_date 取最新）；站点数据更新（页面解析、站点刷新）只写站点种子主表与站点种子快照表。
- **右侧（下载器种子）**：数据来自**下载器种子主表** + 该种子在**下载器种子快照表**中的**最新一条**；关联关系由下载器种子主表的 `site_seed_id` 指向站点种子主表，表示该下载器种子当前匹配的站点种子；下载器同步只写下载器种子主表与下载器种子快照表。
- **Page 一行**：左侧一行 = 一个站点种子（站点主表一条 + 其最新站点快照）；右侧若已关联，则展示对应的下载器种子（下载器主表一条 + 其最新下载器快照），若未关联则无右数据或从下载器拉取候选。

### Page 页面意图与左右表关联设计

- **页面意图**：按站点分块展示「站点做种列表」与「下载器种子」的对应关系。左表展示站点做种，字段来自站点种子主表与站点种子快照表（如 name、size、seeders、bonus_per_hour）；右表展示对应下载器种子，字段来自下载器种子主表与下载器种子快照表，接口中右列统一加 `downloader_` 前缀（如 downloader_hash、downloader_name、downloader_torrent_name、downloader_size、downloader_tracker、downloader_ratio）。通过刷新拉取数据、通过保存把当前关联写回后端。
- **左右表关联**：左右两表**行一一对应**，以左表为基准。每一行 = 一个站点种子 + 与之关联的那条下载器种子（若有）。关联是一对一：一个站点种子最多对应一个下载器种子（表里用下载器种子主表的 `site_seed_id` 指向站点种子）；一个下载器种子最多对应一个站点种子。未关联时右表该行无数据或占位；前端「保存数据」即把当前表格中的左-右对应关系提交后端持久化（写入或更新 `site_seed_id`）。

### 需求

- **左列 = 站点主表 + 其最新站点快照**：左列数据一律来自站点种子主表 + 该种子最新一条站点快照。
- **右列 = 下载器主表 + 其最新下载器快照（仅当已关联时）**：若该站点种子已有关联的下载器种子（下载器种子主表中存在 `site_seed_id` 指向该站点种子），右列展示以**下载器种子主表 + 其最新下载器快照**中存在的字段为准，不依赖下载器 API 获取表中已存数据。
- **仅当需要未关联候选或表中无右数据时才从下载器拉取**：  
  - 已关联行：右列以表中数据为准（见上条）。  
  - 未关联的下载器种子列表（右表用于勾选/拖拽关联的候选）：表中无这些下载器种子记录，需按站点从下载器拉取，并用**站点地址映射**过滤后供前端使用。

### 下载器种子表与配置中下载器的关系（与本节其他需求冲突时以本条为准）

- **落表范围**：下载器种子主表/快照表保存的是「配置中配置的同步下载器」的种子数据；同步时只同步**当前配置里勾选的下载器**，写入表。
- **配置取消后不删表**：若配置中先勾选了下载器 A、表中已有下载器 A 的数据，之后用户取消勾选下载器 A，**数据库中下载器 A 的数据不删除**，保留。
- **Page 查询按当前配置过滤**：Page 相关查询接口（做种列表、右表已关联数据、未关联候选等）中，**只使用当前配置中的下载器**：查表时只查下载器种子主表字段 `downloader_name`（所属下载器）属于当前配置的同步下载器列表的记录；从下载器 API 拉取未关联候选时也只拉当前配置的下载器。因此 Page 上不会展示已从配置中取消的下载器（如 A）的数据。

## 三、右边匹配与 Page 接口数据源

### 需求：右边匹配只依赖站点地址映射

- 某站点对应哪些下载器种子（用于右表展示与关联候选），应**只**由插件配置的**站点地址映射**决定：站点 domain → 若干 Tracker 关键词/域名，下载器种子主表字段 `tracker`（或解析后的 `tracker_domain`）与这些关键词/域名匹配即视为该站点的候选。
- 不得用主项目站点信息里的「站点地址」参与该匹配。

### 自动匹配逻辑（站点种子 ↔ 下载器种子）

- **步骤顺序**：先按 Tracker 筛选 → 再按名称多语言分词匹配 → 再按总大小相近判定。
- **1）Tracker 筛选**：仅在该站点「站点地址映射」对应的下载器种子候选集合内进行匹配（即下载器种子的 tracker/tracker_domain 与站点地址映射匹配的才参与）。
- **2）名称分词与匹配**：对站点种子名称与下载器种子名称按不同语言分词（中文使用分词、英文/数字按词切分），得到 token 集合；按 token 重叠度（如共同 token 占比）从高到低排序，优先匹配「相关度更高」的候选。
- **3）总大小判定**：在名称匹配相关度较高的候选中，再判断下载器种子总大小与站点种子总大小是否相差不大（如相对误差在约定范围内）；若某候选同时满足名称相关度高且大小相近，则视为自动匹配成功。
- 调用自动匹配时，传入的下载器种子列表应为已按上述 Tracker 筛选后的该站点候选，以保证先 Tracker 再分词再大小的顺序。

### 需求：Page 所用接口的数据源

- **原则**：Page 页面调用的、与做种/匹配相关的接口中，**除 plugindata 外，不得再查主项目其它表**。
- **允许的数据源**：插件 plugindata、插件四张表（站点种子主表/快照表、下载器种子主表/快照表）、下载器 API（仅当需要未关联下载器列表或表中确实无右数据时）、插件配置本身（仅读配置项，不读主项目站点表/用户数据表）。
- **需满足的约束**（数据与页面展示的对应关系）：  
  1. **Page 上的站点列表**（配置里「显示站点」勾选后、Page 中展示的各个站点块及站点名）：数据来自插件配置/plugindata 中保存的已选站点信息，不来自主项目站点表。  
  2. **Page 左侧表**（做种列表）：行数据来自插件**站点种子主表与站点种子快照表**，展示字段与第四节表结构一致：主表 name、size、pubdate、torrent_id、seed_attr，站点快照表 seeders、weight、T_weeks；某站点无做种记录时按第一节通过页面解析写入后再展示，不读主项目用户数据表。魔力/h（bonus_per_hour）等数值由约束 3 的魔力数据源支持。  
  3. **Page 上的魔力相关展示**（每小时总魔力、各种子魔力/h、以及站点魔力参数 T0/N0/B0/L 等）：数据来自 plugindata 或页面解析时写入的存储，不读主项目用户数据表。  
  4. **Page 右侧表**（下载器种子列表及关联/未关联候选）：已关联行的展示数据来自插件**下载器种子主表与下载器种子快照表**，展示字段与第四节两表一致，接口返回时右列统一加 `downloader_` 前缀：主表对应 downloader_hash、downloader_name（所属下载器）、downloader_torrent_name（种子名称）、downloader_size、downloader_tracker、downloader_tracker_domain、downloader_added_at，快照表对应 downloader_ratio、downloader_uploaded、downloader_downloaded、downloader_seeding_time、downloader_status、downloader_save_path、downloader_category、downloader_tags；未关联候选从下载器 API 拉取。某站点对应哪些下载器种子、以及右表展示与关联候选，仅由配置页「站点地址映射」+ 下载器 tracker 决定，不用主项目站点信息里的「站点地址」参与匹配。

## 四、表结构（按站点种子与下载器拆分为四张表）

数据按**站点种子**与**下载器**两条线拆分：站点侧一张主表 + 一张快照表，下载器侧一张主表 + 一张快照表，共四张表。站点数据更新只写站点两表，下载器同步只写下载器两表；关联通过下载器种子主表的 `site_seed_id` 指向站点种子主表。

### 1. 站点种子主表（表名 `ptbonuscalc_site_seed`）

| 字段名 | 类型 | 说明 |
|--------|--------|--------|
| id | 自增主键 | 主键 |
| mapping_key | String(512) | 唯一，格式 `site_domain\|torrent_id` |
| site_domain | String(256) | 站点域名，索引 |
| torrent_id | String(384) | 种子唯一键（torrent_id），索引 |
| name | String(1024) | 种子名称 |
| size | BigInteger | 种子大小（字节） |
| pubdate | String(64) | 发布时间 |
| seed_attr | String(32) | 主辅属性：main / aux |
| created_at | DateTime | 创建时间 |

### 2. 站点种子快照表（表名 `ptbonuscalc_site_seed_snapshot`）

| 字段名 | 类型 | 说明 |
|--------|--------|--------|
| id | 自增主键 | 主键 |
| site_seed_id | Integer, FK | 关联站点种子主表 id，CASCADE 删除，索引 |
| snapshot_date | Date | 快照日期，索引 |
| snapshot_time | String(32) | 当日快照时刻（如 "14:30:00"） |
| web_status | String(32) | 网页状态：exists / not_exists |
| seeders | Integer | 做种人数 |
| weight | Float | 权重 |
| T_weeks | Float | 发布周数 |
| created_at | DateTime | 创建时间 |

唯一约束：`(site_seed_id, snapshot_date)` 每天一条。

### 3. 下载器种子主表（表名 `ptbonuscalc_downloader_seed`）

| 字段名 | 类型 | 说明 |
|--------|--------|--------|
| id | 自增主键 | 主键 |
| downloader_hash | String(64) | 下载器种子 hash，索引 |
| downloader_name | String(128) | 所属下载器（下载器名称，如 qb、tr），索引 |
| downloader_torrent_name | String(1024) | 种子名称（该种子在下载器中的名称/标题） |
| size | BigInteger | 下载器中的种子大小 |
| tracker | String(512) | tracker 原始 URL |
| tracker_domain | String(256) | 解析后的 tracker 域名，索引 |
| added_at | DateTime | 添加到下载器的时间 |
| site_seed_id | Integer, FK 可空 | 当前匹配的站点种子主表 id，索引 |
| seed_attr | String(32) | 主辅属性：main / aux |
| main_hash | String(64) | 主下载器种子 hash，seed_attr为aux时这个才需要填写 |
| main_tracker_domain | String(256) | 主下载器种子 tracker_domain，seed_attr为aux时这个才需要填写 |
| created_at | DateTime | 创建时间 |

关联：`site_seed_id` 指向站点种子主表，表示该下载器种子当前对应哪个站点种子；未匹配可为空。`downloader_name` 为所属下载器，`downloader_torrent_name` 为种子名称；downloader_name 用于区分多下载器并参与「按当前配置过滤」（见第二节）。

### 4. 下载器种子快照表（表名 `ptbonuscalc_downloader_seed_snapshot`）

| 字段名 | 类型 | 说明 |
|--------|--------|--------|
| id | 自增主键 | 主键 |
| downloader_seed_id | Integer, FK | 关联下载器种子主表 id，CASCADE 删除，索引 |
| snapshot_date | Date | 快照日期，索引 |
| snapshot_time | String(32) | 当日快照时刻 |
| downloader_status | String(64) | 标准化状态：seeding / downloading / paused / error / uploading / deleted / unknown |
| ratio | Float | 分享率 |
| uploaded | BigInteger | 上传量 |
| downloaded | BigInteger | 下载量 |
| seeding_time | Integer | 做种时长（秒） |
| save_path | String(1024) | 保存路径 |
| category | String(256) | 分类 |
| tags | String(512) | 标签 |
| created_at | DateTime | 创建时间 |

唯一约束：`(downloader_seed_id, snapshot_date)` 每天一条。
